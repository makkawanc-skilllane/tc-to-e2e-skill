# เทียบ TC กับ Figma, ตั๋ว และโค้ด

## หา frame

- ดูคอลัมน์ที่ `TC_TO_E2E.md` บอกว่าใช้อ้าง Figma (มักเป็น Comments / Notes) TC หนึ่งข้ออาจอ้างหลาย frame หรือหลาย state
- ถ้า session มี Figma MCP: เปิด frame นั้นโดยตรง แล้วอ่านข้อความบนจอ, สี chip/พื้นหลัง, ลำดับปุ่ม และ state ที่ต่างกัน
- ถ้าเปิดไม่ได้: ขอให้ผู้ใช้ export PNG โดยใส่ลิงก์เต็มของแต่ละ frame
  `https://www.figma.com/design/<file>?node-id=<id>` (ไม่ใช่แค่ node-id) แล้วหยุดรอจนได้ภาพ
- เก็บภาพที่ใช้อ้างอิงไว้ใน `doc/<feature>/figma/` และใส่ลิงก์ frame ไว้ในชื่อไฟล์หรือใน README

## ตาราง "เทียบ TC / ตั๋ว / Figma / โค้ด"

จดไว้ใน doc ของ feature 1 แถวต่อ 1 ข้อที่ต้อง assert:

| TC / Step | Expected ในชีต | ตั๋ว (AC) | Figma (frame) | โค้ด (ไฟล์:บรรทัด) | ตัดสิน |
|---|---|---|---|---|---|
| TC-HOME-003 / 2 | "คาบถัดไป" | AC2 "คาบถัดไป" | `node-id=12-34` "คาบถัดไป" | `i18n/th/home.ts:41` "พร้อมสอน" | assert ตามชีต → คาดว่า Fail |

## ลำดับการตัดสิน

1. **assert ตาม Expected ในชีตเสมอ** ห้ามแก้ Expected ให้ตรงกับระบบ
2. โค้ดต่างจากชีต: ปล่อยให้เคสตก แล้วจดลงตาราง "คาดว่า Fail" พร้อมอ้างไฟล์/ฟังก์ชันที่ทำให้ผลต่าง
3. Figma ต่างจากตั๋ว หรือโค้ดตรงกับ Figma แต่ไม่ตรงกับตั๋ว: **ยังไม่ต้องเปิดบั๊ก** ให้ตั้งเป็นคำถาม BA พร้อมลิงก์ frame
4. ฟีเจอร์ยังไม่ลงในโค้ดเลย: จัดเป็น "ยังไม่พัฒนา" และใช้ `test.fixme` ไม่ใช่บั๊ก

## สีและภาพ

ถ้า Expected พูดถึงสีหรือภาพ (เช่น "พื้นสีเขียว") ให้ตรวจผ่าน attribute ที่โค้ดใช้เลือกสี (`data-tone`, `data-chip`, class)
แล้วเขียนใน doc ว่าตรวจสีด้วยวิธีนี้ ไม่ได้วัดจากพิกเซล
